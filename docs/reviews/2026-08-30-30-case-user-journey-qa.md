# Relay 10 场景 / 30 用例用户旅程测试报告

> 日期：2026-08-30
> 分支：`codex/relay-p0-demo-recovery`
> 测试入口：`npm run test:scenarios`

## 测试方法

- 使用 Playwright 驱动本机稳定版 Chrome，访问生产构建预览；
- 使用真实点击、输入、下拉选择、刷新、确认弹窗和手机视口操作；
- 每条用例开始前恢复确定性工作区，并清空服务端演示房间；
- Agent 场景由 Playwright 在网络边界注入可重复的 MiniMax 协议夹具，避免模型
  波动掩盖产品回归；生产代码不包含本地计划回退；
- MiniMax 在线连通、真实回复和真实浏览器发布链路已在 M11 单独验证；
- 双端场景使用两个页面或两个完全隔离的浏览器上下文；
- 离线场景在页面加载后切断网络，再完成接受与提交结果。

## 第一轮失败复核

第一轮为 28/30，两条失败都来自测试脚本，而不是产品行为：

1. 受邀人拒绝后会正确返回事项列表。测试最初切换到姐姐后没有重新点击该事项，
   却直接查找详情页负责人；补齐真实点击步骤后通过。
2. 测试初始化最初在每次刷新时清空 `localStorage`，错误地破坏了“减少动态”设置；
   改为每个测试会话只清空一次后，刷新持久化通过。

修正后完整重跑全部 30 条，不是只重跑失败项，结果为 30/30。

随后运行仓库统一门禁 `npm run verify`：lint、严格 TypeScript、10 个单元
测试、生产构建和 51 个 Chrome E2E 全部通过；新增 30 条矩阵也在整套回归中
再次全部通过。

## 观察结论

- 当前事项 SOP 与界面效果一致：创建不会直接替别人接受，接受后负责人变化，
  调整与拒绝都会回到发起者，完成结果对相关视角可见，发起者可重开。
- Agent 在确认发布前不改变事项数据；发布后的三步计划进入真实事项与邀请流程。
- 搜索、筛选、空状态、错误链接、手机布局和恢复操作均给出可理解反馈。
- 浏览器标签页、隔离手机/电脑上下文和已加载页面的离线操作均通过。
- 本轮没有修改产品功能，也没有发现需要阻断演示的产品缺陷。
