# Relay 黑客松 Demo 规格

> 版本：v1.0  
> 日期：2026-08-29  
> 依据：Relay PRD v1.1 与 2026-08-29 需求评审

## 0. 用户语言与操作流程

界面不要求用户理解“接棒 / 接住”。主演示用日常中文呈现同一责任变化：

```text
林然记录事情
→ 确认下一步、完成标准和需要重新联系她的情况
→ 把单事项邀请发给小雨
→ 小雨选择“可以，我来处理”或“这次我不方便”
→ 接受后显示“这一步由小雨负责”
→ 小雨完成后，双方看到“已完成”
```

四个用户状态统一为“待我处理 / 等待回复 / 对方处理中 / 已完成”。
“接棒”“接住”“接棒者”和“责任轨道”只可作为内部设计或工程称呼，
不能成为用户完成操作前必须学习的产品术语。

## 1. Demo 要证明什么

评委体验后能在 5 秒内回答：原本谁负责下一步、现在谁负责、对方答应做什么、哪些情况仍要联系林然，以及林然是否还需要主动追问。

主演示路径不打字、不扫码、不等待网络、无页面滚动，总操作不超过 6 次。

## 2. 人物与故事

### 林然

- 29 岁，独居职场女性；
- 周五临时出差，周日晚返回；
- 养猫“布丁”；
- 使用微信、备忘录和截图管理生活。

### 小雨

- 林然的朋友；
- 住得离宠物诊所较近；
- 没有 Relay 账号；
- 曾在林然出差时帮助喂猫。

## 3. 英雄事项 fixture

| 字段 | 值 |
|---|---|
| id | `matter-cat-checkup` |
| 标题 | 周六带布丁完成复诊 |
| 背景 | 林然周五临时出差，周日晚回来 |
| 时间 | 重置时生成的下一个周六 09:30 |
| 当前下一步 | 08:40 接到布丁，09:20 前到达诊所 |
| 必需资料 | 纸质报告放在猫包侧袋 |
| 完成标准 | 布丁完成复诊并安全回家，复诊结论发给林然 |
| 协作者 | 小雨 |
| 初始责任 | 林然 |
| 负荷 | 比较挂心 |
| 演示令牌 | `demo-cat-checkup` |

责任边界：

> 如果医生建议当日手术、住院、更改治疗方案或产生重大额外费用，请先联系林然，不替她作医疗决定。

## 4. 首页辅助数据

| 事项 | 区域 | 当前责任 | 叙事作用 |
|---|---|---|---|
| 把备用钥匙放到门卫 | 待我处理 | 林然 | 对照仍由自己行动 |
| 等房东确认热水器维修时间 | 等待回复 | 房东 | 说明等待不同于对方已确认负责 |
| 上次出差期间上门喂猫 | 已完成 | 小雨 | 建立可信关系历史 |
| 替妈妈取体检报告 | 对方处理中 | 姐姐 | 打开页面时已能理解第三分区 |

首页每个分区最多显示 1～2 张卡，保证英雄事项移动前后的区域同时可见。

## 5. 路演舞台 `/demo`

桌面布局：

```text
┌──────────────────────────────────────────────────────┐
│ Relay 标识              Demo 控制：阶段 / 重置 / 动效 │
│                                                      │
│   ┌──── 林然手机 ────┐       ┌──── 小雨手机 ────┐   │
│   │ 今天 / 创建 / 状态 │  →→   │ 分享事项 / 回应   │   │
│   └─────────────────┘       └─────────────────┘   │
│                                                      │
│     当前讲解提示，仅演示者可见，不进入产品 UI         │
└──────────────────────────────────────────────────────┘
```

小雨手机在分享前保持弱化轮廓；生成分享后滑入并显示事项。两部手机在同一 DOM 和状态源内，英雄动画不得尝试跨真实浏览器窗口使用共享布局动画。

## 6. 负责人变化线

所有核心界面复用同一组件：

```text
林然 ●────────○ 小雨   等待回应
林然 ○────────● 小雨   这一步由小雨负责
```

- 责任点、人物名和持久状态文字同时变化；
- 动画约 680ms；
- 其他反馈 160～240ms；
- `prefers-reduced-motion` 开启时取消位移，只切换实心点、颜色和文案。

## 7. 正式 90 秒脚本

| 时间 | 画面 | 操作/旁白 |
|---|---|---|
| 0～10s | 林然首页三个状态区 | “最累的不只是做，而是一直记着下一步轮到谁。” |
| 10～24s | 点击预置语句 | 确定性生成英雄事项 |
| 24～38s | 事项确认 Sheet | 展示下一步、完成标准和责任边界 |
| 38～50s | 邀请预览 | 点击“发给小雨” |
| 50～62s | 小雨端进入 | 无账号看懂请求 |
| 62～72s | 小雨回复 | 点击“可以，我来处理” |
| 72～83s | 双端同步 | 负责人圆点移动，卡片进入“对方处理中”区域 |
| 83～90s | 三张扩展场景卡 | 搬家、父母照护、伴侣协作后收束 |

## 8. Demo 控制器

不出现在正式导航，只在 `/demo` 可见：

- 重置到 `initial`；
- 跳到 `shared`；
- 跳到 `accepted`；
- 跳到 `completed`；
- 切换林然/小雨视角；
- 开关减少动态效果；
- 复制当前演示路由。

任何阶段跳转必须得到完整合法状态，不能只改一张卡的颜色。

## 9. 技术与素材约束

- `seedVersion` 控制 fixture 迁移；
- 相对日期在重置时重新计算；
- `localStorage` 持久化；
- `BroadcastChannel` 同步同源标签页；
- 所有头像、字体、图标和关键素材本地打包；
- 不读取真实病历、地址、电话或外部 PDF；
- Vercel 配置 SPA rewrite；
- 本地 build 断网可运行；
- 准备 90 秒完整录屏。

## 10. 验收

- [ ] 从初始状态到小雨接受不超过 45 秒；
- [ ] 小雨端 20 秒内能说出要做什么和哪些决定不能做；
- [ ] 接受后 5 秒内能看出责任变化；
- [ ] 两个同源标签页 500ms 内同步；
- [ ] 375px 无横向滚动；
- [ ] 桌面投屏双手机内容可辨认；
- [ ] 正式路径无打字、扫码、网络等待和滚动；
- [ ] 一键重置恢复完整 fixture；
- [ ] 减少动态效果时语义完整；
- [ ] 黄金路径连续 10 次无失败。
