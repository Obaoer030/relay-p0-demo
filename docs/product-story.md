# Relay 设计背景与独立产品价值

## 为什么做 Relay

很多生活负担不是“事情太多”，而是一个人必须持续记住背景、下一步、等待对象和例外情况。宠物复诊、租房维修、搬家交接、异地父母照护等事项往往跨越多人和多天；发起者即使发出消息，仍需要解释、确认和追问。

Relay 将这种隐形的协调劳动变成一个可见的责任结构：

```text
事项上下文 → 明确下一步 → 当前责任人 → 完成标准 → 决策边界
```

## 为什么不只是微信消息

微信擅长沟通，但聊天流按时间组织。事项状态会被新消息覆盖，截图、资料、决定和“现在轮到谁”分散在上下文中。发送一句“你能帮我吗”也不等于对方已经接受责任。

Relay 按事项组织：

| 微信聊天 | Relay |
|---|---|
| 保存说过什么 | 保存事情现在由谁推进 |
| 信息随消息流下沉 | 事项持续显示当前状态 |
| 接受、拒绝和完成常靠语气推断 | 接棒状态明确、可拒绝、可完成 |
| 背景和资料分散 | 单事项包集中必要上下文 |
| 容易把执行决定与重大决策混在一起 | 明确执行范围与必须联系发起者的边界 |
| 发起者通常仍要主动追问 | 接受后持久提示无需继续追问 |

Relay 不替代微信。微信仍是关系和沟通入口；Relay 是聊天消息之外的事项状态层。未来可以把 Relay 链接通过微信发送，但责任、边界和进度保留在 Relay 中。

## 为什么值得成为独立软件

只有独立的事项状态层，才能跨越一次聊天持续回答：

1. 原本由谁推进；
2. 现在由谁推进；
3. 对方具体接住什么；
4. 什么算完成；
5. 哪些决定不能代替发起者做；
6. 发起者现在是否还需要行动。

传统待办主要保存“我要做什么”，聊天保存“我们说了什么”；Relay 保存“这件生活事务的责任现在在哪里”。

## 典型场景

- 临时出差：朋友接住宠物复诊，医疗方案仍由主人决定；
- 租房维修：等待房东确认上门时间，避免把“等待”误认为“我忘了做”；
- 搬家交接：室友负责验房，但赔付决定仍联系发起者；
- 异地父母照护：兄弟姐妹接住取报告或陪同步骤；
- 伴侣生活：明确采购、预约和跟进由谁推进；
- 旅行与行政：把资料、时间和完成标准集中在一个事项中。

## 设计语言

Warm Editorial 使用暖米白、深棕和克制砖红，强调成年人的可信、平静与情绪安全。责任轨道是品牌级符号：即使不依赖颜色或动画，人物端点、实心责任点和状态文字仍能解释责任转移。
