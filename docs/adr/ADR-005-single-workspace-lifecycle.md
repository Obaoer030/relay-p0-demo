# ADR-005：单一工作台状态与完整事项闭环

> 状态：Accepted
> 日期：2026-08-29
> 决策范围：完整 Demo 的运行时状态、事项 SOP 与桌面测试指针

## 背景

当前应用同时挂载早期路演状态和完整工作台状态。虽然两者各自可运行，但同一
事项可能出现两份互不相同的事实；事项编辑器还允许直接选择“对方处理中”或
“已完成”，绕过对方确认和完成结果。桌面模拟手机时，自定义光标又隐藏了系统
光标，降低了测试可见性。

## 决策

1. `WorkspaceState` 是唯一运行时状态源；移除早期 `RelayProvider`。
2. `/demo` 进入完整可探索工作台，不再呈现独立双手机舞台。
3. `/r/demo-cat-checkup` 从同一 `WorkspaceMatter` 读取并写回确认结果。
4. 生命周期只能由业务动作推进：邀请、接受、提出调整、拒绝、完成、重新打开。
5. 编辑器只修改事项约定；已接受事项的关键约定变化后自动回到等待确认。
6. 完成动作必须保存结果说明；已完成事项可由发起者重新打开。
7. 精细指针设备保留系统光标，并叠加高对比定位环；触摸与减少动态模式降级。

## 后果

- 演示、公开协作页、用户切换和完整工作台看到同一份数据与动态。
- 自动化黄金路径改为走完整产品流程，而不是操作演示控制器。
- 旧路演状态实现可从运行时代码和测试中删除。
- 仍是同源 localStorage/BroadcastChannel 演示，不宣称真实跨设备协作。

## 验收

1. 应用只挂载一个状态 Provider；`/demo` 没有第二套控制器。
2. 用户不能通过表单直接伪造已接受或已完成状态。
3. 接受、调整、再次确认、完成结果和重新打开均有状态与动态证据。
4. `/r/demo-cat-checkup` 与工作台在 500ms 内同源同步。
5. 375×812 与 1440×900 无溢出；桌面鼠标和定位环均清晰可见。
