# ADR-001：黑客松采用 Demo-first 本地架构

> 状态：Accepted  
> 日期：2026-08-29  
> 决策范围：Relay 黑客松 P0

## 背景

原 PRD 同时要求离线演示、localStorage、真实跨设备分享、Supabase 匿名登录、RLS、Edge Function、令牌安全、实时同步和生产级状态恢复。单人 48～72 小时无法在保证前端完成度的同时可靠交付这些能力。

黑客松当前要证明的是：用户能否看懂并感受到一次有边界的责任接棒，而不是证明生产级多人系统已经完工。

## 决策

P0 使用单一、确定性的前端状态源：

```text
React + TypeScript + Vite
→ Context/useReducer
→ localStorage 持久化
→ BroadcastChannel 同源标签页同步
→ /demo 双手机路演舞台
```

- P0 不接数据库、账号、Realtime 或运行时 AI；
- `/r/demo-cat-checkup` 是同源模拟分享路由；
- P0 明确不承诺不同设备或浏览器配置间同步；
- Supabase 降为 Stretch Goal，且不能阻塞本地黄金路径；
- 正式演示不依赖网络、扫码、打字或外部资源。

## 评估过的方案

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 完整 Supabase 生产方案 | 真实跨设备，技术完整 | Auth、RLS、函数、令牌、测试与部署风险高 | P0 否决 |
| 本地 + 远程自动双模式 | 既可离线又可真实分享 | 两套数据源容易分叉，恢复逻辑复杂 | 否决 |
| 本地确定性 Demo | 稳定、快速、最利于 UI 打磨 | 不是真实跨设备产品 | P0 采用 |
| 本地完成后增加极简 Supabase | 可作为技术加分项 | 仍需额外半天和安全测试 | Stretch Goal |

## Stretch Goal 边界

只有在 P0 通过全部验收并仍有至少半天时才开始：

- 两张业务表：`matters`、`handoffs`；
- 一个 Edge Function；
- 三类公开动作：获取事项、接受/婉拒、完成；
- 不使用 Realtime；页面聚焦刷新或短轮询；
- 访客不直接写数据库；
- 绝不通过关闭 RLS 或暴露 secret/service role key 换取速度。

## 后果

正面结果：前端、动效、演示稳定性和路演叙事获得更多时间；单一状态源更容易测试和重置。

限制：评委手机扫码无法更新演示者电脑；必须诚实说明当前是交互原型。真实跨设备协作仍需后续技术验证。

## 重新评审条件

出现以下任一条件时重新评估：

1. 比赛规则明确要求真实多设备联网；
2. 黄金路径已连续运行 10 次无失败；
3. 响应式、责任轨道、双手机舞台和录屏均已完成；
4. 剩余可支配开发时间不少于半天。
