# ADR-002：从路演舞台扩展为完整交互式 Demo

> 状态：Accepted
> 日期：2026-08-29
> 决策范围：Relay 黑客松完整体验版

## 背景

ADR-001 保障了一条稳定的 90 秒接棒路径，但只有路演舞台不足以支持评委自由探索。新的明确要求是：评委既能观看核心故事，也能像真实用户一样浏览实际数据、创建和管理事项、理解产品为什么独立于聊天工具存在，并在手机与电脑浏览器中完成体验。

## 决策

在保留 `/demo` 和 `/r/demo-cat-checkup` 的前提下，将 `/` 扩展为可部署的响应式 Web 应用：

- 完整应用壳：移动端底部导航、桌面端侧栏与内容区；
- 事项模块：总览、搜索、筛选、创建、编辑、删除、详情与状态变更；
- 协作模块：等待回复、对方处理中、已完成和婉拒记录；
- 关系模块：可信协作者及共同完成记录；
- 动态与设置：活动时间线、演示数据重置、减少动态和产品说明；
- 数据使用版本化 `localStorage`，包含可读的多场景种子数据，用户操作刷新后保留；
- 继续使用 `BroadcastChannel` 做同源标签页同步；
- 所有页面移动优先，并在桌面形成真正的产品界面，而不是手机模型居中展示。

## 手机方案

当前采用响应式 Web，而不是重写微信小程序：

- 一个 URL 同时服务手机和电脑，适合评委快速打开；
- 复用现有 React/Vite 代码和自动化测试；
- 不依赖微信主体、开发者资质、审核和小程序发布流程；
- 后续可以增加 PWA 安装能力，但不作为本轮完成依赖。

微信小程序是运行在微信容器内的另一套应用交付方式，通常需要小程序账号、平台配置、审核，并可能使用不同组件和 API。它适合依赖微信分发的正式产品，但不是“网页适配手机”的必要条件。

## 诚实边界

本轮是完整交互式 Demo，不宣称生产级 SaaS：

- 不接真实账号、云数据库、支付、消息推送或跨设备实时协作；
- 不部署，也不处理线上域名或凭据；
- “真实数据”指应用中真实可创建、修改、持久化和同步的演示数据，不是真实个人隐私数据；
- 未来上线若要求不同设备共享同一账户数据，必须新增后端、身份、权限和安全设计。

## 验收

评委无需进入 `/demo` 也能在 `/` 自由完成：查看总览 → 搜索或筛选 → 新建事项 → 编辑详情 → 改变状态或邀请协作者 → 查看关系与活动 → 刷新后数据仍在。关键路径在 375×812 与 1440×900 均可操作。
