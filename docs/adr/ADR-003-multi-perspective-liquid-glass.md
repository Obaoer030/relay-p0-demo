# ADR-003：多角色共享演示与 Calm Tech Glass

> 状态：Accepted
> 日期：2026-08-29
> 决策范围：Relay 完整交互式 Demo

## 背景

完整工作区已经支持事项 CRUD、协作、关系人与活动，但数据默认只从林然
视角解释。评选现场需要展示同一事项如何从发起者流向协作者，以及双方在
不同时间看到什么。用户同时明确要求视觉更有科技感，并选择类似 Apple
玻璃材质的空间层次，但不要落入常见的“AI 模板感”。

## 决策

工作区增加四个确定性演示角色：林然、小雨、姐姐、陈屿。右上角视角切换
器改变当前观察者，首页、事项、协作、关系人和活动都按当前角色解释同一份
共享状态。

同一事项保存创建人、当前负责人、参与人和受邀人。界面状态根据观察者转换：

```text
发起者：等待回复 → 对方处理中 → 已完成
受邀人：等我确认 → 待我处理 → 已完成
```

受邀人可以确认负责或表示这次不方便；当前负责人可以完成事项。所有动作写入
同一个 reducer、localStorage 和 BroadcastChannel 状态，不建立四份假数据。

视觉升级为 Calm Tech Glass：浅中性底、钢蓝主色、深海军蓝文字和少量珊瑚
人情味；透明分层主要用于导航、角色切换和关键浮层。高密度文字、表单和
状态反馈保持足够不透明。

明确排除所谓“AI 味”：紫色霓虹渐变、发光球、星光或魔法棒图标、神经网络
装饰、渐变文字、过量胶囊按钮、每张卡片都透明，以及没有产品意义的漂浮动画。
科技感来自清楚的数据关系、精确排版、层级、材质和负责人状态变化。

## 边界

- 角色是本地演示视角，不是真实登录账号；
- 同一浏览器与同源标签页共享状态，不宣称手机与电脑真实云同步；
- 不增加数据库、身份、权限后端、运行时 AI 或部署；
- 视觉效果必须支持减少动态、键盘焦点和无 `backdrop-filter` 回退。

## 验收

1. 右上角可在四个角色间切换，刷新后保留当前视角；
2. 每个角色拥有不同的可见预制数据；
3. 林然发出的待确认事项可由小雨确认负责，切回林然后显示对方处理中；
4. 小雨完成后，林然看到同一事项已完成和对应活动；
5. 婉拒后事项仍由发起者处理；
6. 375×812 与 1440×900 均无溢出、遮挡或不可读玻璃层；
7. 全路径、同源同步、离线、减少动态和十连跑继续通过。
