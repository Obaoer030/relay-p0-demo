# ADR-006：文字版协作编排 Agent 与共享演示房间

> 状态：Accepted
> 日期：2026-08-29

## 背景

用户希望 Relay 不再要求先填写结构化表单，而是让用户用自然语言说明一件事，
由 Agent 拆解步骤、建议负责人并识别缺失信息。用户将提供 MiniMax API Key，
本阶段不开发语音录制或转写。同时，最终路演会在手机和电脑上共同展示，现有
localStorage 只能完成同一浏览器来源内的标签页同步。

## 决策

1. 新建事项默认进入文字版 Agent Composer，手工表单保留为明确备用入口。
2. Agent 返回严格验证的 `AgentPlanDraft`：计划标题、背景、步骤、负责人、完成
   标准、边界、缺失字段、假设和下一条澄清问题。
3. Agent 一次只追问一个会阻塞执行的高价值问题；信息完整后进入可编辑预览。
4. 用户确认后，每个步骤才通过既有 reducer 创建为真实事项。非本人负责人进入
   等待确认，Agent 不替受邀者接受。
5. MiniMax 使用服务端 OpenAI-compatible Chat Completions；默认模型由环境变量
   配置。API Key 不得以 `VITE_` 前缀暴露给客户端。
6. 无 Key、超时、非法结构或供应商失败时使用标明来源的确定性回退，不伪装成
   真实 MiniMax 结果。
7. 同一 Relay 服务进程提供一个内存演示房间，通过 HTTP + Server-Sent Events
   同步完整 WorkspaceState，使不同浏览器/设备可以演示同一份数据。

## 安全边界

- Agent 只能提出草案，不得绕过发布确认、受邀人确认或 reducer 守卫。
- 不在提示词中发送与当前计划无关的完整工作区历史。
- 只接受白名单用户 ID、分类、优先级和长度受限的文本。
- 演示房间无身份与权限隔离，只能用于受控路演环境；不得宣称生产安全。
- 生产部署仍需要持久数据库、房间访问控制、速率限制、审计和密钥管理。

## 验收

1. 用户输入一段自然语言后能收到步骤草案或一条明确澄清问题。
2. 确认计划前 WorkspaceState 不发生变化。
3. 确认后生成的每个步骤都有负责人、下一步和完成标准。
4. MiniMax Key 只从服务端环境变量读取；仓库只提交 `.env.example`。
5. 无 Key 时完整 Agent 演示仍确定性通过，并明确显示“本地演示引擎”。
6. 两个隔离浏览器上下文通过同一服务在一秒内看到状态变化。
7. 375×812 与 1440×900 均可完成输入、澄清、预览和发布。
